# Models rollout recovery and evidence boundary — 2026-09-07

## Current production state

The models rollout was rejected and subsequently recovered. Release remains paused.

- Restored the nine affected channels' complete model records, including Axis `max-output-tokens`.
- Restored the previous Go image and removed the attempted synchronizer/container network. All 47 services were running at recovery acceptance.
- Kept CPA `v7.2.152`, Sub2API `0.2.1`, original external plugins, and database writes. No historical database was restored.
- Recovery public acceptance: 265 full records, 92 authorized identities, 71 visible records; 4,536,744 bytes. Whole-record fidelity, routing identity, output alias, ETag 304, and opaque unauthorized 404 passed. Eleven monitoring samples reported no regression.
- These results establish recovery, not successful rollout, long-term stability, inference/WS coverage, or provider-binding correctness. Restoring the old Go image does not deliver the candidate's GMI skip feature.

## Proven restoration defect and tested recovery

On the selected stock CPA image, an actual-configuration models PATCH round trip loses Axis `max-output-tokens`. The upstream `OpenAICompatibilityModel` type in `internal/config/config_types.go` does not represent this field. This is data loss, not alias/order normalization.

The isolated recovery retained the current YAML text outside the affected `models` nodes, replaced only those nodes from the stage baseline, and submitted the result through authenticated `PUT /v0/management/config.yaml`. Complete persisted model records, supported Management projection, native identities/eight inspected capability fields, and persistence through restart matched the baseline control. Production used this tested path after checking the captured configuration hash and stopped synchronizer. No Core restart or database restore was needed in production.

This emergency recovery does not establish a general concurrent full-config-write contract. Earlier synthetic models-only tests must not be treated as proof of lossless recovery for arbitrary actual configurations.

## Isolated captures and subsequent fixture audit

The first isolated run captured three epochs: settled baseline, immediately after writing the captured post-attempt configuration through the raw-YAML interface, and a repeat with a fresh cache key. Configuration, Management, native actually consumed by Go, Go output, and cache each contained all three NIM members. Cache MISS/HIT payloads matched the captured Go bytes exactly. Artifact hashes, secret exclusion, and absence of container OOM/restarts were independently rechecked.

This was **not** a complete historical replay: the inventory shim returned controlled data instead of executing CPA api-call, injected credentials when forwarding reads, and did not implement some metadata POSTs. There were 53 fixture-handler exceptions; Go's fail-open behavior allowed membership observations to complete. Those observations remain scoped to that fixture and do not prove real credential forwarding or general metadata failure handling.

The additional exact-Rust-candidate experiment was stopped at an assertion requiring every disabled channel's models to remain unchanged. The fixture also logged 17 handler exceptions. Both the failed trial and its harness are retained; it was not rerun or converted into a pass.

### Existing contract, not a new exception

`openspec/specs/cpa-model-sync/spec.md` lines 9–16 explicitly allow safe best-effort refresh of disabled channels; inability to refresh through CPA may leave old models without blocking acceptance. Lines 159–178 preserve CPA credential boundaries. `cpa-model-sync/README.md` lines 66–71 likewise specify full models replacement while preserving the disabled flag and other non-model fields.

Therefore an unconditional assertion that **disabled models must never change** was an unsupported extra condition. In the stopped trial, the five disabled channels' flags remained true and all their non-model fields were unchanged, while their models changed. This does not establish a candidate defect. Equally, the success-returning api-call shim cannot prove the real CPA authentication/forwarding path would permit those refreshes. No assertion was silently relaxed and no candidate fix was justified from this result.

### Evidence boundary and next gate

- Historical NIM disappearance remains unproved beyond the recovered configuration/outcome/cache observations.
- The completed controlled run did not reproduce it; the Rust experiment is inconclusive because of fixture substitution and assertion applicability.
- Do not keep modifying fixtures until a run passes.
- Any further isolated experiment must transparently retain real CPA Management authentication, credential resolution and PATCH, controlling only upstream directory responses; declare transport changes and unmodeled metadata operations in advance. Keep the exact NIM set and all applicable non-model/credential/activation assertions.
- Otherwise, obtain a separately authorized bounded read-only on-site capture. It must capture the native response actually consumed and the direct Go response for the same epoch, not substitute later reads. No production switch, inference replay, state reset, or cache purge is implied.
