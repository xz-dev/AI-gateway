## Why

Live serving today: production accounts 1/4/5/6 point directly at AISIX (`base_url=http://aisix:3000/v1`); AISIX forwards to its configured CPA targets. The retained internal APISIX entrance and its Sub2API-side relay are deployed and reachable but carry no active production serving placement. Catalog evidence shows the two backends expose different raw inventories (CPA standard and `client_version=1` both list 223 raw IDs; AISIX lists 37; overlap 21; AISIX-only 16; enriched union 239), so direct-AISIX accounts cannot reach CPA-only models and a CPA catch-all cannot reach AISIX-only models. The operator selected catalog-based routing behind a unified entrance: classify each model against raw source memberships before inference, prefer CPA, fall back to AISIX, and fail honestly when no authoritative catalog is available.

## What Changes

- Classify model IDs **before inference** using raw source catalog snapshots: `model ∈ C` (CPA raw IDs) routes to CPA, including overlap; `model ∉ C ∧ model ∈ A` (AISIX raw IDs) routes to AISIX; absent from both authoritative catalogs is model-not-found. No inference probe decides membership.
- No cross-backend retry at the entrance: a chosen backend's 429, 5xx, timeout, or stream error never re-routes the request to the other backend. One backend is selected per request. Sub2API's existing account pool retries and AISIX's internal combo retry/cooldown budgets are untouched.
- Unknown source availability is not empty membership. When no usable decision exists (cold start, required snapshot unusable), the entrance returns a service-unavailable classification instead of masquerading as model-not-found. Known `C` members stay routable when only the AISIX snapshot is unavailable; a failed CPA fetch never degrades into an "AISIX-only" guess.
- Reuse the retained internal APISIX instance (the `apisix-models` gateway) as the single classification and forwarding seam: Sub2API → internal APISIX → CPA or AISIX; AISIX then routes to its configured CPA targets as today. Making it the serving path requires a separately approved account `base_url` migration (accounts are on AISIX today); retained connectivity alone is not serving placement.
- Bounded route seam: new scoped high-priority entrance routes classify the model-bearing JSON HTTP inference paths (`POST /v1/responses`, `POST /v1/chat/completions`, including Sub2API `http_bridge` output) and run before the legacy HTTP alias rewrite/CPA-direct routes, so the original requested ID reaches the selected backend untouched. Legacy direct-WS transport and other non-classified endpoints keep their existing behavior outside the scope. Malformed or unsupported payloads on a classified path fail explicitly, never silently fall through to CPA.
- Reuse the models-enricher Go source collection, cache, and merge as the single in-process snapshot owner: retain the distinct raw memberships `C` and `A` (never derived from the enriched union), initialize at startup and refresh on a bounded periodic cadence independent of catalog-client traffic, and expose a small internal four-outcome routing-index view (`cpa`, `aisix`, `not_found`, `unavailable`, plus generation) for the entrance.
- Real catalog endpoints: `GET /v1/models` without or with empty `client_version` returns the standard OpenAI `data[]`/`id` projection (canonical build version 1) from the sidecar; non-empty `client_version` keeps the existing Codex `models[]`/slug behavior; `/models-table` keeps its current inventory version. The old "no-version never reaches the sidecar" contract is superseded.
- Raw source collection stays direct to the CPA and AISIX raw endpoints; only raw source collection is prohibited from looping through the unified entrance — client catalog delivery through the entrance is intended and retained.
- Preserve existing streaming, request/response bodies and model IDs, provider error behavior, Sub2API account/group authorization, and Pi non-chat model filtering. Field precedence, identity admission, `bare_models_takeover`, and static/custom rules are unchanged.
- Supersede the earlier AISIX-first premise: no AISIX global wildcard route, no replicating all CPA models into AISIX, and the previous "all CPA-backed accounts point directly at the AISIX hostname" placement gives way to the unified entrance — with an explicit coordination gate for accounts opted into the parallel Headroom change.

## Capabilities

### New Capabilities

- `cpa-first-catalog-routing`: Catalog-based backend selection at the unified inference entrance — classification precedence, the four-outcome routing-index contract, raw-membership authority, source-failure versus valid-empty semantics, and single-backend no-retry behavior.

### Modified Capabilities

- `apisix-cpa-gateway`: The internal instance's scoped inference forwarding changes from "everything not a models-manifest request goes to CPA" to membership-based selection between CPA and AISIX on the classified HTTP inference paths; the models route split now sends both standard and Codex models requests to the sidecar; WS transport and non-classified routes stay outside the selector.
- `codex-models-enricher`: The sidecar becomes the routing-snapshot owner in addition to the manifest builder — it retains distinct raw memberships with startup initialization and bounded periodic refresh, exposes the internal routing-index view, and answers standard OpenAI models requests alongside the Codex manifest.
- `safe-aisix-cutover`: The account-placement requirement is reconciled with the unified entrance; production CPA-backed accounts target the internal entrance (which selects AISIX where AISIX owns the model) instead of pointing directly at the AISIX hostname, without blindly overwriting opted-in Headroom placements.

## Impact

- `models-enricher/` (Go): snapshot ownership with startup/periodic lifecycle, raw membership retention, internal routing-index endpoint, standard OpenAI list projection, generation-pinned catalog caches, tests alongside the existing suite.
- `apisix-models/apisix.yaml` plus its Lua: scoped high-priority selector routes for the classified paths, per-request bounded membership lookup (no entrance-side result cache), upstream selection between CPA and AISIX; legacy WS-alias/models-table routes and Codex-models split retained, conflicting legacy HTTP alias rules removed from the classified scope.
- `compose.yaml`: an internal APISIX → AISIX edge following the existing relay/network conventions; no new public bindings.
- Sub2API: no code or image change. Accounts currently serve via `http://aisix:3000/v1`; a separately approved migration updates only the owned `base_url`/necessary routing fields using the latest complete credentials object, preserving peer retry/pool edits, with rollback restoring the prior AISIX serving behavior — not a route-only CPA catch-all revert. Production rollout, backups, and rollback require separate explicit approval and are out of scope here.
- Parallel changes `fix-sub2api-error-propagation`, `preserve-end-to-end-session-affinity`, and `add-headroom-context-compression` remain untouched. Headroom is a separate, not-yet-implemented, independently approved change: any combined deployment with opted-in Headroom accounts is gated on that owner's approved rebase so Headroom's downstream targets the internal entrance (`Sub2API → Headroom → internal APISIX → CPA/AISIX`) instead of bypassing the selector or losing compression.
- Verification uses the existing Go test suite, Lua checks, and isolated fake-upstream integration harnesses; no provider inference quota is spent on routing demonstrations.
