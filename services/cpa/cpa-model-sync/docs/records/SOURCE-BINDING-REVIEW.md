# 来源绑定候选：部署边界

## 本阶段决定

先部署 Rust 白名单和 Go 的 CPA 成员归属机制。**生产元数据来源链与映射保持原样，仅增加 `skip_channels: [gmicloud]`；不部署本轮新增来源链、映射或来源快照。** 本地元数据候选保留，未取得身份依据的项不启用；核心镜像升级不在本阶段重复执行。

## 有限核对结果

- 94 个新增显式 `lookup_ids` 的查询目标存在于捕获的 models.dev/modelparams.dev 数据中。来源快照与 `TestConfigured*` 验证精确查询、优先级、空值边界和合并执行，不验证转售服务实际提供的模型身份。
- 对 `commandcode`、`gmicloud` 等转售 ID，现有材料主要是公开模型名称、发布者前缀和目标记录；尚未取得转售方的明确 canonical-ID 对应声明或等价的身份证据。**不能仅凭名称、大小写或前缀对应认定身份绑定成立。** 包括看似直观的映射，新增候选统一暂缓部署。
- 已有明确配置的查询映射属于生产基线；复用这些映射不等于新增转售方绑定也自动获证。当前不扩大旧例外范围。
- `kimi-coding` 经私有备份中的 auth 类型核实为 `kimi` OAuth；已撤销新增外部链。`codex`、`supergrok` 同样不新增外部来源链。
- `fast`、`free`、尺寸、日期等未证实等价的变体不自动归一化。不存在目标或字段的情形仍保留未知，不推算输入限制。

## 本阶段验收依据

1. 生产元数据配置除显式 GMI 跳过项外与新阶段基线一致；候选镜像只携带该生产基线配置，不内嵌本地新增来源映射。
2. 实际同步策略加载 NIM 三项精确允许值，以及 ShuaiAPI 的 `^claude-`；示例文件正确不作为加载成功证据。
3. Rust 仅更新五类受管配置的 models；Go 以 CPA 成员为准，不再次决定受管集合。
4. 新阶段独立备份和回滚保持当前已升级 CPA/Sub2API 镜像及新写入数据，不使用旧核心升级备份覆盖数据库。
5. 离线 HTTP 与上线即时成员、授权、字段、生命周期验证分开留证；自然刷新观察在即时验证之后进行。

元数据绑定依据审查留待此交付阶段之后继续。此记录不代表来源链已部署或当前 OpenSpec 已完成。

## GMI 用户授权例外

用户明确决定“跳过 gmi，gmi cloud 本来就好像没有这个权限”。Rust 与 Go 均通过显式 `skip_channels` 跳过该 prefix 的目录请求；Rust 不进入 models 写回，Go 保留 CPA 原生成员。不得修改 GMI 启用状态、凭据、既有 models 或出口规则。Rust 单独记录 `skipped`，不记作更新、未变化或测试通过。仅 GMI 获此例外，其他启用渠道失败仍阻塞发布；不再为本次交付修复 GMI URL 或研究出口权限。
